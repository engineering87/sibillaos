# SibillaOS 0.10.0

The supply cycle: the release where keeping the machine current became
product instead of chore. The biggest upstream jump in the project's
history, verified point by point before trusting it; the kernel as a
stated choice; the context window governed instead of discovered; the
catalog moved to its next model generation; and the pieces CI caught
along the way, fixed where users would have hit them. Systems
installed from 0.4.0 onward receive this release through a plain
`sudo apt update && sudo apt upgrade`, and CI keeps proving that
survival on every push.

## What is new

The big freshness pass: ollama 0.33.2 -> 0.40.11, with every
integration point re-verified before the bump (placement format,
OLLAMA_NO_CLOUD, installer pinning, /v1 surface, registry manifest
format - all intact); vLLM v0.27.1 -> v0.32.0, carrying three fixed
GHSAs including a chat-template resource exhaustion; whisper.cpp
re-pinned to the binary build matching v1.9.5 after upstream moved
assets off semantic tags, with fresh recorded hashes and the
fail-closed build unchanged.

The kernel, stated and switchable: `sibilla kernel status|hwe`. The GA
kernel stays the appliance default (supported for the whole LTS life);
HWE is the deliberate opt-in for hardware the GA kernel predates - AMD
Strix Halo does not exist for 6.8's amdgpu, while HWE ships 6.17 -
with the rolling nature printed before installing and the GA kernel
kept bootable from GRUB.

The context window, governed: left alone, the engine sizes its KV
cache from visible memory, and on unified-memory machines that
silently reserves tens of gigabytes for context nobody asked for -
hollowing the very RAM the large-tier floors assume. The hardening
drop-in pins 8192 tokens; `sibilla model context N` raises it
deliberately with the trade stated, `context default` removes the
override. `sibilla doctor` now also quotes the engine's own "offloaded
N/M layers to GPU" line: the proof the accelerator is in use, with the
spill quantified.

The catalog's next generation: Qwen3.5 (Apache-2.0 verified at the
source, non-gated, 256K context) joins as the new default family - 4B
on cpu, 9B and 27B on consumer-gpu, the 122B-A10B MoE in the large
tier at a 100 GB floor - while the Qwen3 entries stay for continuity.
Qwen3-Embedding-0.6B (official, Apache-2.0) joins beside nomic for
multilingual RAG. The digest updater learned two vision-era
exclusions: mmproj companions and sharded quants.

Structured outputs, activated: both engines already enforce JSON
schemas through the standard response_format parameter (constrained
decoding on ollama, vLLM 0.32's stable machinery), so the work is
docs/structured-outputs.md, a stdlib worked example, and a CI run.

The WebUI listener inherits the gateway's TLS (local CA in internal
mode, the already-held certificate in acme), the OIDC redirect URL and
cookie follow suit, and every Caddyfile-only toggle now reloads the
gateway gracefully instead of restarting it - the fleet CI test found
caddy hitting systemd's start rate limit on quick toggle sequences, a
wall any user would have hit too.

And the machine looks like what it is: the README architecture
diagram redrawn to the real topology (the gateway as the only door,
six loopback services behind it, fleet past the machine's edge), the
SSH banner teaching the new commands, the social assets saying the
current breadth, and the ISO's GRUB menu wearing the quiet-corner
splash - guarded top to bottom, so anything that cannot render falls
through to the text theme unchanged.

The release procedure itself is now a document (docs/releasing.md),
because the post-tag half is the half that gets forgotten; the roadmap
records the LTS-only base policy as a non-goal and the 26.04 LTS jump
as a dedicated upcoming cycle.

## What has been verified

Everything the previous releases established, plus: the first
install-test after the catalog landed doubled as the qwen35-arch smoke
test (hf.co pull of the new default family on a real machine); the
context governance end to end (default pinned, override landing,
removal restoring - including the drop-in ordering bug the assert
caught, where hardening.conf silently out-voted the override);
`sibilla kernel status` telling the truth on the runner; structured
outputs under the engine-discrimination policy; the speech pipeline on
the b5454 binaries; and the gateway render validated across every
webui/oidc/speech/mcp/tls combination. The upgrade path from the
published 0.9.1 remains asserted on every push.

## Installation

On an existing Ubuntu 24.04 machine:

```console
$ curl -fsSL https://engineering87.github.io/sibillaos/apt/sibillaos-archive-key.asc \
    | sudo gpg --dearmor -o /usr/share/keyrings/sibillaos-archive-keyring.gpg
$ printf 'Types: deb\nURIs: https://engineering87.github.io/sibillaos/apt/\nSuites: ./\nSigned-By: /usr/share/keyrings/sibillaos-archive-keyring.gpg\n' \
    | sudo tee /etc/apt/sources.list.d/sibillaos.sources
$ sudo apt update && sudo apt install llmd
$ sudo sibilla setup
```

Reversible with `sudo sibilla remove`, CI-verified. From the ISO
(amd64): `.part` files plus `SHA256SUMS`, reassemble, verify, write to
USB. From the cloud image (amd64/arm64): verify against
`SHA256SUMS-cloud-<arch>`, boot with your cloud-init user-data.

## Known limitations

Vision is registry-only for now: hf.co-pulled GGUFs are text-only
because ollama does not fetch the mmproj companion, so among catalog
entries only qwen3.5:122b sees images - widening this is an early
decision of the next cycle. OIDC protects the WebUI, not the API.
Fleet runs hosts sequentially by design. The large tier still means
larger than VRAM, not larger than RAM. Rate limiting is per-IP.
Air-gapped payloads cover the Ollama engine. vLLM on physical
datacenter GPUs remains the standing v1.0 debt. The curated catalog
only contains permissively licensed, non-gated models.
