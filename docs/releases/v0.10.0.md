# SibillaOS 0.10.0

The supply cycle: the release where keeping the machine current became
product instead of chore - taken to its conclusion. If the cycle's
theme was freshness, the base itself belonged in it: SibillaOS now
ships on Ubuntu 26.04 LTS, the biggest upstream jump in the project's
history rides along verified point by point, the kernel is a stated
choice, the context window is governed instead of discovered, the
catalog moved to its next model generation and learned to see, RAG
gained its missing middle, and the documentation got a home. Systems
installed from 0.4.0 onward receive this release through a plain
`sudo apt update && sudo apt upgrade`, and CI keeps proving that
survival on every push.

## What is new

The base, jumped: Ubuntu 26.04 LTS on both install paths (ISO and
cloud image), with the GA kernel now 7.0 - AMD Strix Halo works out
of the box, so `sibilla kernel hwe` becomes the opt-in for hardware
newer still, its story rewritten. The jump was executed with a fact
sheet gathered before touching a file, and its fallout became product
fixes where users would have hit them: the installer restores the
full archive before pulling universe packages, the appliance claims
its whole disk at install time (the stock LVM layout starved the
WebUI image pull), and a disabled service never leaves a failed unit
behind.

The big freshness pass: ollama 0.33.2 -> 0.40.11, with every
integration point re-verified before the bump (placement format,
OLLAMA_NO_CLOUD, installer pinning, /v1 surface, registry manifest
format - all intact); vLLM v0.27.1 -> v0.32.0, carrying three fixed
GHSAs including a chat-template resource exhaustion; whisper.cpp
re-pinned to the binary build matching v1.9.5 after upstream moved
assets off semantic tags, with fresh recorded hashes and the
fail-closed build unchanged.

The context window, governed: left alone, the engine sizes its KV
cache from visible memory, and on unified-memory machines that
silently reserves tens of gigabytes for context nobody asked for -
hollowing the very RAM the large-tier floors assume. The hardening
drop-in pins 8192 tokens; `sibilla model context N` raises it
deliberately with the trade stated, `context default` removes the
override. `sibilla doctor` now also quotes the engine's own "offloaded
N/M layers to GPU" line: the proof the accelerator is in use, with the
spill quantified.

The catalog's next generation: Qwen3.5 (Apache-2.0 verified at the
source, non-gated, 256K context) joins as the new default family - 4B
on cpu, 9B and 27B on consumer-gpu, the 122B-A10B MoE in the large
tier at a 100 GB floor - while the Qwen3 entries stay for continuity.
Qwen3-Embedding-0.6B (official, Apache-2.0) joins beside nomic for
multilingual RAG.

And the catalog learned to see: the registry exception, created for
the large tier's sharded GGUFs, is now capability-gated (architecture
changelog v0.17) because vision is the same shape of gap - ollama's
hf.co pull fetches the model GGUF and never the mmproj projector, so
every hf.co entry is text-only by construction. qwen3.5:9b joins as
the additive consumer-gpu vision option, its model-layer digest
recorded from the registry manifest, never a default. docs/vision.md
states the limit honestly.

Reranking, the missing middle of RAG: `sibilla rerank enable` serves
`/v1/rerank` behind the same keys - retrieve wide with embeddings,
rerank the candidates, hand the model the best few. Underneath: a
pinned llama.cpp server (build b11669, per-asset sha256 recorded at
pin time, only llama-server and its libraries ship) on loopback in
the standard sandbox, serving Qwen3-Reranker-0.6B digest-verified
from the signed catalog. The GGUF is a vetted community conversion -
the official weights ship none, and most conversions are broken for
the rerank endpoint - so CI asserts a relevance ordering on every
push: a bad conversion cannot ship. docs/rerank.md shows the RAG
pipeline.

Structured outputs, activated: both engines already enforce JSON
schemas through the standard response_format parameter (constrained
decoding on ollama, vLLM 0.32's stable machinery), so the work is
docs/structured-outputs.md, a stdlib worked example, and a CI run.

The WebUI listener inherits the gateway's TLS (local CA in internal
mode, the already-held certificate in acme), the OIDC redirect URL and
cookie follow suit, and every Caddyfile-only toggle now reloads the
gateway gracefully instead of restarting it - the fleet CI test found
caddy hitting systemd's start rate limit on quick toggle sequences, a
wall any user would have hit too.

The documentation has a home: https://engineering87.github.io/sibillaos/
serves docs/ as a proper site (MkDocs Material, pinned like every
other dependency), sharing the one GitHub Pages site with the APT
repository - the site at the root, /apt/ byte-for-byte where installed
systems resolve it. Deploys happen only on tags, so the published
documentation is always the released one.

And the machine looks like what it is: the README architecture
diagram redrawn to the real topology (the gateway as the only door,
six loopback services behind it, fleet past the machine's edge), the
SSH banner teaching the new commands, the social assets saying the
current breadth, and the ISO's GRUB menu wearing the quiet-corner
splash - guarded top to bottom, so anything that cannot render falls
through to the text theme unchanged.

The release procedure itself is now a document (docs/releasing.md),
because the post-tag half is the half that gets forgotten; the legal
posture is stated in the README and the root NOTICE; and the roadmap
records the LTS-only base policy as a non-goal.

## What has been verified

Everything the previous releases established, now proven end to end
on the 26.04 base: both install paths, Secure Boot, the air-gapped
VM, the upgrade from the published 0.9.1, and the fleet, OIDC, speech
and MCP flows. Plus: the first install-test after the catalog landed
doubled as the qwen35-arch smoke test (hf.co pull of the new default
family); the context governance end to end (default pinned, override
landing, removal restoring - including the drop-in ordering bug the
assert caught); the rerank endpoint with its relevance assertion;
`sibilla kernel status` telling the truth on the runner; structured
outputs under the engine-discrimination policy; the speech pipeline
on the b5454 binaries; and the gateway render validated across every
webui/oidc/speech/rerank/mcp/tls combination.

## Installation

On an existing Ubuntu LTS machine (26.04 is the appliance base and
what CI proves; the packages declare no release-specific dependency):

```console
$ curl -fsSL https://engineering87.github.io/sibillaos/apt/sibillaos-archive-key.asc \
    | sudo gpg --dearmor -o /usr/share/keyrings/sibillaos-archive-keyring.gpg
$ printf 'Types: deb\nURIs: https://engineering87.github.io/sibillaos/apt/\nSuites: ./\nSigned-By: /usr/share/keyrings/sibillaos-archive-keyring.gpg\n' \
    | sudo tee /etc/apt/sources.list.d/sibillaos.sources
$ sudo apt update && sudo apt install llmd
$ sudo sibilla setup
```

Reversible with `sudo sibilla remove`, CI-verified. From the ISO
(amd64): `.part` files plus `SHA256SUMS`, reassemble, verify, write to
USB. From the cloud image (amd64/arm64): verify against
`SHA256SUMS-cloud-<arch>`, boot with your cloud-init user-data.

## Known limitations

Vision requires a registry-sourced entry: hf.co-pulled GGUFs are
text-only because ollama does not fetch the mmproj companion, so the
catalog marks which entries see (qwen3.5:9b, qwen3.5:122b) and the
defaults stay text-only. OIDC protects the WebUI, not the API. Fleet
runs hosts sequentially by design. The large tier still means larger
than VRAM, not larger than RAM. Rate limiting is per-IP. Air-gapped
payloads cover the Ollama engine; the speech and rerank models can be
pre-placed by hand and are verified in place. vLLM on physical
datacenter GPUs remains the standing v1.0 debt. The curated catalog
only contains permissively licensed, non-gated models.
