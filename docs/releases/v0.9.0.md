# SibillaOS 0.9.0

The appliance grows senses and a span. This cycle adds a voice
(local speech-to-text), an organization's front door (OIDC for the
WebUI), a reach across machines (fleet orchestration over plain SSH)
and a human moment at first boot (the model selection menu) - each
built the only way this project builds anything: pinned upstreams,
verified artifacts, opt-in toggles, and CI that drives the real flow
rather than narrating it. Systems installed from 0.4.0 onward receive
this release through a plain `sudo apt update && sudo apt upgrade`,
and CI keeps proving that survival on every push.

## What is new

Speech: `sudo sibilla speech enable` serves /v1/audio/transcriptions
behind the same gateway and keys, speaking the OpenAI transcription
shape (srt and vtt included, so subtitles come out directly). The
engine is whisper.cpp, repackaged from its pinned release like llmfit;
the Whisper base model arrives digest-verified from the signed catalog
- and a file already in place verifies instead of downloading, which
is the air-gapped path for free. Without ffmpeg the endpoint accepts
16 kHz WAV and says so; with ffmpeg (a Recommends, not a dependency)
it converts most formats. Audio never leaves the machine.

OIDC for the WebUI: `sudo sibilla oidc enable ISSUER CLIENT_ID` puts
the chat interface behind your identity provider - Entra, Keycloak,
Google, any OIDC issuer; the appliance bundles none. The client secret
is read from stdin, never from arguments. In between sits oauth2-proxy,
pinned and verified against the checksums upstream publishes, sandboxed
on loopback. The WebUI container itself now binds loopback only, with
the gateway fronting it on port 3000 in every configuration. API
clients are untouched: bearer keys as before, because the boundary
between human and machine access should be a clean one.

Fleet: `sibilla fleet apply|check|status` pushes the declarative
profile and aggregates drift and health across every machine in a
plain hosts file - over your own SSH, with no agent, no credential
store, and no key distribution, because profiles carry no secrets by
design and your ssh config already knows your machines. Each
subcommand aggregates to one exit code, so a cron line becomes a fleet
probe.

The first-boot model menu: the appliance ISO's first boot draws a
numbered menu of the curated models that fit the machine, on the
console, and keeps the installer's choice after thirty seconds - so
unattended installs behave exactly as before, and automation (declared
profiles, air-gapped payloads, cloud images) never sees it. It offers
no large-tier and no embedding entries: the giant stays an explicit
opt-in, as the roadmap principle demands.

Supply freshness: ollama 0.32.1 -> 0.33.2 (resolved-metadata caching
roughly halves time to first token; prefill restore points), vLLM
container v0.25.1 -> v0.27.1 (security patches plus DeepSeek-V4,
Kimi K3 and Qwen3.5 optimizations). OLLAMA_NO_CLOUD stays pinned and
CI keeps asserting it. Expert streaming upstream re-checked: still an
open llama.cpp PR, so the large tier's claim ("larger than VRAM, never
larger than RAM") is unchanged and ds4 remains gated on having
something to pin.

Credits where due: the README gains a "Built on" section naming every
pinned upstream, its author and its license.

## What has been verified

Everything the previous releases established, plus: a real spoken WAV
transcribed through the authenticated gateway (401 without a key,
closure on disable, model digest verified); the full OIDC
authorization-code flow against a pinned dex - login redirect,
credentials into the provider's form, callback, cookie, authenticated
landing, direct access after disable; the fleet surface over a real
sshd (apply converging, check clean on a converged host, an
unreachable host reddening the aggregate without hanging, and the
machine left as found); the model menu's whole contract in lint
(selection, timeout, invalid input, every automation gate); and the
gateway rendering validated across every webui/oidc/speech/mcp/tls
combination. The upgrade path from the published 0.8.0 remains
asserted on every push.

## Installation

On an existing Ubuntu 24.04 machine:

```console
$ curl -fsSL https://engineering87.github.io/sibillaos/apt/sibillaos-archive-key.asc \
    | sudo gpg --dearmor -o /usr/share/keyrings/sibillaos-archive-keyring.gpg
$ printf 'Types: deb\nURIs: https://engineering87.github.io/sibillaos/apt/\nSuites: ./\nSigned-By: /usr/share/keyrings/sibillaos-archive-keyring.gpg\n' \
    | sudo tee /etc/apt/sources.list.d/sibillaos.sources
$ sudo apt update && sudo apt install llmd
$ sudo sibilla setup
```

Reversible with `sudo sibilla remove`, CI-verified. From the ISO
(amd64): `.part` files plus `SHA256SUMS`, reassemble, verify, write to
USB. From the cloud image (amd64/arm64): verify against
`SHA256SUMS-cloud-<arch>`, boot with your cloud-init user-data -
optionally including an `/etc/llmd/profile` the machine converges on.

## Known limitations

OIDC protects the WebUI, not the API; port 3000 speaks plain HTTP
(HTTPS for the WebUI listener is tracked for a later cycle - on
untrusted networks keep it on a trusted segment). Fleet runs hosts
sequentially by design. The large tier still means larger than VRAM,
not larger than RAM: SSD expert streaming waits on a pinnable
upstream. Rate limiting is per-IP; per-key fairness stays deferred.
Air-gapped payloads cover the Ollama engine. vLLM on physical
datacenter GPUs remains the standing v1.0 debt. The curated catalog
only contains permissively licensed, non-gated models.
