# SibillaOS 0.8.0

The big-model bet. The v0.7 distribution push met silence, and the answer is not louder posting but a bet on the loudest niche there is: running very large models on hardware you own. One principle bounds the whole cycle, stated in the roadmap so no future cycle erodes it: large models are additive support, never the default. First boot keeps serving what the machine honestly runs. Systems installed from 0.4.0 onward receive this release through a plain `sudo apt update && sudo apt upgrade`, and CI keeps proving that survival on every push.

## What is new

The large tier: a dedicated catalog tier for models bigger than your GPU but within your RAM. The pinned engine does layer offload - layers past the VRAM spill to system RAM and run on the CPU - so "larger than VRAM" is the honest claim, never "larger than RAM". Two entries open the tier: gpt-oss:120b (Apache-2.0, ~80 GB floor) and qwen3:235b (Apache-2.0, ~170 GB floor). Everything about the tier is opt-in and fail-closed: no large model is ever auto-selected at first boot; `sibilla model use` refuses a model past the machine's RAM floor before downloading a single byte, with no `--force`, because a model past physical memory does not run slowly, it freezes the box in swap; and an opt-in that fits still states its cost (RAM spill, slower generation) before proceeding. `sibilla model list` shows the large entries separately with the RAM each needs, `sibilla status` gains a placement line with the real GPU/CPU layer split reported by the engine itself, and docs/large-models.md says how to measure the cost with `sibilla bench` and when the giant is the wrong call.

The catalog's second source: large models ship as sharded GGUF, which the hf.co pull path does not support, so the Hugging Face-only source policy is extended for the large tier alone to the ollama.com registry. Verification does not change: the registry manifests carry sha256 layer digests, recorded in the signed catalog and checked after every pull like every other model.

Serving guards closed on every path: writing the large-models guide surfaced two real holes on the import path, both fixed in this release. `sibilla model import FILE --use` now enforces the same guards as `use` - an embedding model cannot become the chat model and a large model is refused below the RAM floor (the import itself is kept) - and registry ids no longer double their tag on import.

The third-engine groundwork, recorded rather than shipped: ds4 (DwarfStar) owns the "larger than RAM" story via SSD expert streaming, but upstream has no tags, releases or binaries yet - nothing to pin, so the integration stays gated. An upstream issue requesting tagged releases, with the Debian packaging offered in exchange, is SibillaOS's first visible ecosystem participation. The design is already decided and recorded: when ds4 becomes pinnable it will coexist with ollama on unified-memory machines behind llama-swap (per-model routing, upstream start/stop so the resident model yields RAM to the giant), and every other machine keeps the straight gateway-to-engine path.

Man pages: `man sibilla` now documents every subcommand - setup, status, model, key, tls, metrics, webui, mcp, apply, connect, bench, doctor, remove - shipped gzipped in llmd-hw.

## What has been verified

Everything the previous releases established, plus: the RAM floor refusal (exact model, bare-name tag omission covered), the exclusion of large entries from first-boot auto-selection, the honest large listing with per-entry RAM requirements, the catalog policy lints (registry entries must be large-tier, large entries must carry a RAM floor), the man page rendered with warnings fatal and asserted inside the deb on the apt path, and the registry digest recording alongside the 161 Hugging Face digests. The upgrade path from the published 0.7.0 remains asserted on every push.

## Installation

On an existing Ubuntu 24.04 machine:

```console
$ curl -fsSL https://engineering87.github.io/sibillaos/apt/sibillaos-archive-key.asc \
    | sudo gpg --dearmor -o /usr/share/keyrings/sibillaos-archive-keyring.gpg
$ printf 'Types: deb\nURIs: https://engineering87.github.io/sibillaos/apt/\nSuites: ./\nSigned-By: /usr/share/keyrings/sibillaos-archive-keyring.gpg\n' \
    | sudo tee /etc/apt/sources.list.d/sibillaos.sources
$ sudo apt update && sudo apt install llmd
$ sudo sibilla setup
```

Reversible with `sudo sibilla remove`, CI-verified. From the ISO (amd64): `.part` files plus `SHA256SUMS`, reassemble, verify, write to USB. From the cloud image (amd64/arm64): verify against `SHA256SUMS-cloud-<arch>`, boot with your cloud-init user-data - optionally including an `/etc/llmd/profile` the machine converges on.

## Known limitations

The large tier runs models larger than VRAM, not larger than RAM: SSD expert streaming waits on a pinnable ds4 upstream. Large-tier inference on machines with real spill has not yet been benchmarked on physical hardware by the project - `sibilla bench` exists so adopters can measure and share. Plain HTTP with mandatory bearer keys by default: enable TLS with `sibilla tls` before exposing the port. Rate limiting is per-IP; per-key fairness stays deferred. Air-gapped payloads cover the Ollama engine. vLLM on physical datacenter GPUs remains the standing v1.0 debt. The curated catalog only contains permissively licensed, non-gated models.
