# SibillaOS 0.11.0

The release where the label comes off. Ten releases in, "proof of
concept" described the past: SibillaOS now presents itself by what CI
proves on every push - the ISO built, booted under BIOS and UEFI with
Secure Boot, installed end to end, serving a real completion at first
boot, and upgraded in place from the published release. Around that
claim, this cycle gave the machine an identity, eyes on itself, a
guard at the door, and a decided future for the large tier. Systems
installed from 0.4.0 onward receive this release through a plain
`sudo apt update && sudo apt upgrade`.

## What is new

The brand, with one voice: the tagline everywhere (nothing leaves the
machine), a horizontal wordmark in light and dark variants, the
quiet-corner palette on the documentation site, a recomposed social
card served as the og image for every shared link, a dedicated
small-size favicon, and appliances stating their identity in
/etc/issue before anyone logs in. A new high-level overview drawing
says what the project is at a glance; the detailed diagram grows true
again with the loopback row at eight services.

The machine learns to show itself: `sibilla fetch` (the box at a
glance beside the oracle eye - now the opening frame of the README
demo), `sibilla mem` (system RAM, per-GPU VRAM, the models actually
resident with their CPU/GPU split read from the engine's own process
list, each llmd service's memory, the store on disk), `sibilla model
info` (parameters, quantization, training context and embedding width
from the GGUF metadata beside the catalog's view and the runtime
state), and `sibilla key usage` (traffic accounting from the
structured access log, with the per-key attribution limit stated
honestly against the archive caddy - the log never contains the keys).

The guard stage, pulled forward from the next cycle's candidacy:
`sibilla guard enable` screens chat requests with Qwen3Guard on a
loopback verdict server - the official safety template travels inside
the digest-pinned GGUF, a dependency-free stdlib proxy forwards the
untouched request or refuses with an explicit `content_blocked`
error, and the guard fails closed. One pinned llama.cpp serves both
sidecars. CI vets the verdict on every push: a blatant probe must
come back blocked, or the pinned GGUF does not ship. Stated honestly:
a 0.6B classifier is a filter, not a guarantee - which is why
`sibilla doctor --redteam` also arrives, running NVIDIA's garak
against your own gateway (deliberately not shipped; the command
prints the pinned install).

The operator's lifecycle completes: `sibilla backup` and `restore`
carry the machine's configuration in one mode-600 archive (keys
included, models re-fetched digest-verified, identity markers never
traveling - the engine is a hardware decision the target makes
itself), and `sibilla transcribe` turns the existing speech stack
into a batch CLI with zero new dependencies.

The performance governors: `sibilla model warm on` keeps the served
model resident (the first request after a quiet hour stops paying the
reload, at the stated cost of the RAM), and `sibilla model cache q8`
quantizes the KV cache with flash attention enabled as the engine
requires - half the context memory for a negligible quality cost,
with the revert path written in the drop-in itself.

The engine decision (architecture changelog v0.19): the ds4 route
closes - upstream publishes no releases by deliberate choice, so the
gate held for three cycles will never open, through nobody's fault -
and the llama.cpp route opens on evidence: a dispatch-run spike proved
the pinned b11669 server against the gateway contract point by point
on a real MoE, with a richer /v1/models than ollama's and native
timings in every response. Integration is the next cycle's core.

The catalog gains the Velvet family (Almawave's Italian models,
Apache-2.0 verified at the source, non-gated): 2B on cpu and 14B on
consumer-gpu through vetted community GGUFs, the official 14B
safetensors on the vLLM datacenter tier - additive entries, the
defaults do not move.

And the firewall learns its missing half: the gateway's per-source
rate limit now guards IPv6 too, with a /64 source mask because
rotating addresses inside one's own /64 is free. Evaluated and
rejected in the same audit: ufw limit on SSH, which would break
fleet's and CI's rapid sequential connections.

## What has been verified

Everything the previous releases established, plus: the guard
end to end (a harmless request through to the engine, a blatant probe
blocked with the explicit error, disable restoring the straight
path); backup, key rotation, restore, and the old key answering
again; the governors landing their environment, inference surviving
the quantized cache, and the reverts cleaning up - including the
systemd start-limit lesson, applied to the engine the way v0.10
applied it to the gateway; the v6 rate limit in the rules file, in
the kernel, and masked; transcribe on the CI-generated recording;
fetch, mem, model info and key usage asserted on the freshly
installed machine reading real state; and the llama.cpp contract
spike, run on dispatch with its verdict in the job summary.

## Installation

On an existing Ubuntu LTS machine (26.04 is the appliance base and
what CI proves; the packages declare no release-specific dependency):

```console
$ curl -fsSL https://engineering87.github.io/sibillaos/apt/sibillaos-archive-key.asc \
    | sudo gpg --dearmor -o /usr/share/keyrings/sibillaos-archive-keyring.gpg
$ printf 'Types: deb\nURIs: https://engineering87.github.io/sibillaos/apt/\nSuites: ./\nSigned-By: /usr/share/keyrings/sibillaos-archive-keyring.gpg\n' \
    | sudo tee /etc/apt/sources.list.d/sibillaos.sources
$ sudo apt update && sudo apt install llmd
$ sudo sibilla setup
```

Reversible with `sudo sibilla remove`, CI-verified. From the ISO
(amd64): `.part` files plus `SHA256SUMS`, reassemble, verify, write to
USB. From the cloud image (amd64/arm64): verify against
`SHA256SUMS-cloud-<arch>`, boot with your cloud-init user-data.

## Known limitations

The guard classifies the text of the last user message; images in
vision requests are not classified, and a 0.6B classifier is a
filter, not a guarantee. Per-key usage attribution waits on a log
field the archive caddy cannot write. Vision requires a
registry-sourced entry; the defaults stay text-only. OIDC protects
the WebUI, not the API. Fleet runs hosts sequentially by design. The
large tier still means larger than VRAM, not larger than RAM - the
llama.cpp integration that will move that line is the next cycle's
core. Rate limiting is per source, both families. Air-gapped payloads
cover the Ollama engine; the speech, rerank and guard models can be
pre-placed by hand and are verified in place. vLLM on physical
datacenter GPUs remains the standing v1.0 debt. The curated catalog
only contains permissively licensed, non-gated models.
